# CLAUDE.md — AI Foundation

## Проєкт

AI Foundation — набір плагінів Claude Code для моєї комерційної розробки й самонавчання. Інструмент особистий, але професійного рівня: його збої коштують часу й грошей на реальних проєктах.

## Принципи

1. Контекст один раз: агент знає проєкт з першого повідомлення.
2. Нічого зайвого в клієнтських репозиторіях; клієнтські дані — поза цим репо.
3. Якість продакшн-рівня: тести, версіонування, CI.
4. Спершу виміряй, потім покращуй.
5. Самопокращення — лише через пропозиції, які я затверджую.
6. Безпечна деградація: збій хука пропускає перевірку й не блокує роботу.
7. Нове — лише з реальної потреби; невикористане видаляється.
8. Ізоляція клієнтів: дані й облікові дані одного клієнта не потрапляють у сесію іншого.
9. Спершу вбудовані можливості Claude Code; власне — лише там, де їх бракує.

## Архітектурні правила

- Плагіни поділені за можливостями: `af-core`, `af-controls`, `af-handoff`, `af-metrics`. Новий плагін — лише коли можливість справді окрема.
- Ядро й controls ні від кого не залежать. Залежності — `dependencies` за іменем із semver-діапазоном, ніколи за шляхом.
- Компоненти плагіна — в його корені, не в `.claude-plugin/`. Плагін не постачає `CLAUDE.md` і правила; папку `bin/` не використовуємо; стан не зберігаємо в `${CLAUDE_PLUGIN_ROOT}`.
- Спільний код: канонічне джерело в `shared/`, копії в плагінах, `sync-shared --check` має проходити. Файли поза папкою плагіна не потрапляють у кеш; симлінків не використовуємо.
- Хуки й скрипти — TypeScript на Node 22.18+ (CI: 22 і 24) без кроку збірки, лише «стираний» синтаксис, розширення `.ts` в імпортах, `import type` для типів.
- Хуки реєструються в exec-формі (`node` + шлях у `args`) з явним коротким `timeout`. Exit 2 — лише свідоме блокування; внутрішня помилка → exit 0 і повідомлення про деградацію. Шлях проєкту — з `cwd`, не з `${CLAUDE_PROJECT_DIR}`.
- Windows і Linux: лише прямі слеші в маніфестах і `hooks.json`; у коді — `node:path` і `os.homedir()`; імена файлів у нижньому регістрі; кінці рядків LF.
- Ніколи не читати й не виводити секрети: файли з токенами, `.env`, змінні середовища. Транскрипти й клієнтські дані — лише агрегатами, ніколи вміст.
- Фікстури тестів — лише синтетичні або очищені. Сторонні скіли й плагіни не встановлювати без сканування SkillSpector у статичному режимі.
- Постійний контекст — бюджет: умовні інструкції — скіли з `paths`, обов’язкові правила — хуки. Контекст від хука на старті сесії — до 10 000 символів.
- `SKILL.md` до 500 рядків, найважливіше на початку; `description` + `when_to_use` до 1 536 символів; шаблони — в `assets/`, деталі — в `references/`.
- Спершу вбудоване: `claude plugin validate`, `plugin tag`, `plugin eval`, worktrees, `/init`, OTel. Власне — лише там, де їх бракує.
- Кожна зміна поведінки плагіна — з тестом і записом у `CHANGELOG.md`.

## Структура

- `plugins/` — плагіни; `shared/` — спільний код; `scripts/` — перевірка й синхронізація
- `docs/` — бачення, технічний старт, рішення (`docs/decisions/`)
- Клієнтські дані — у `~/ai-foundation-data/projects/`, не тут

## Команди

- `npm run validate` — уся перевірка: `claude plugin validate --strict` для маркетплейсу й кожного плагіна, наші перевірки, `tsc --noEmit`, sync `--check`, тести, фікстури, секрети. Запускати перед кожним комітом.
- `npm test` — усі тести (хуки й скрипти) без решти перевірок. `npm run validate -- --only <id>` / `--skip <id>` — вибіркові перевірки.
- `npm run sync` — оновити копії спільного коду з `shared/`.
- `npm run metrics:baseline` / `npm run metrics:inventory` — базова лінія метрик / опис транскриптів; звіти в `~/ai-foundation-data/metrics/`.
- `claude --plugin-dir ./plugins` — сесія з локальними плагінами; після змін хуків чи агентів — `/reload-plugins`.
- Реліз: підняти `version` лише в `plugin.json`, запис у `CHANGELOG.md`, `claude plugin tag plugins/<плагін>`.

## Поточний етап

Етап 1 — каркас — завершено 2026-11-20 (реліз 0.1.0). Базова лінія метрик — `docs/decisions/0002-metrics-baseline.md`.

Етап 2 — контекст один раз, потім handoff; чекліст — `docs/tech-start.md`, рішення — ADR 0004 (прийнято). Назви клієнтів і їхніх проєктів у репо не пишемо — лише в `~/ai-foundation-data/`. Робочий ланцюг, рев'ю коду, worktree, ролі, self-learning і нові метрики — **не** на цьому етапі: зупинитися й спитати.

## Де деталі

Читати лише тоді, коли задача цього потребує:

- `docs/vision.md` — що і навіщо: напрями, цілі, скоуп, звірка з матеріалами друга
- `docs/tech-start.md` — рішення до першого рядка коду, середовище, перевірки, критерії готовності етапів, звірка з документацією
- `docs/decisions/` — окремі рішення з поясненням «чому»; нове рішення — новий файл (0001 — факти Claude Code, 0002 — базова лінія метрик, 0003 — рев'ю коду, 0004 — контекст проєкту і база знань)
- `docs/install-check.md` — перевірка встановлення з маркетплейсу
