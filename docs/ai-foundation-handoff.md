# AI Foundation — перенос контексту

Стан на 21.11.2026. Файл переносить контекст проєкту в новий акаунт чи нову сесію Claude: вставте його в інструкції або знання проєкту «AI Foundation». Повні документи — у репозиторії `GUSILLUS/ai-foundation`: `CLAUDE.md`, `docs/vision.md`, `docs/tech-start.md`, `docs/decisions/`.

## Що це

AI Foundation — набір плагінів Claude Code для моєї комерційної розробки й самонавчання. Інструмент особистий (користувач — лише я), але професійного рівня: його збої коштують часу й грошей на реальних проєктах.

Два напрями:

- **Робота:** контекст, контроль і перевірки, handoff, робочий ланцюг (ідея → дизайн → специфікація → план → реалізація → перевірка), метрики, самопокращення з помилок і метрик, оптимізація витрат, ролі (зокрема тестувальник і фахівець з безпеки), стилі, worktrees, звіти, захоплення навчальних моментів (`/capture`).
- **Self-learning** (лише в пет-проєктах): режим навчання «зроби / навчи мене», пет-проєкти з навчальними варіантами кроків, розбір захоплених моментів, карта знань, скаут (`/scout`).

Цілі: не пояснювати контекст повторно; оптимізувати відповіді (якість, формат, вартість); закласти фундамент.

## Принципи

1. Контекст один раз.
2. Локально й портативно: нічого зайвого в клієнтських репозиторіях.
3. Якість продакшн-рівня: тести, версіонування, CI.
4. Спершу виміряй, потім покращуй.
5. Людина затверджує: самопокращення лише через пропозиції.
6. Безпечна деградація: збій хука не блокує роботу.
7. Нове — лише з реальної потреби.
8. Ізоляція клієнтів.
9. Спершу вбудовані можливості Claude Code.

## Ухвалені рішення

- Основне середовище — Claude Code ≥ 2.1.321; Windows і Linux з першого дня.
- Хуки й скрипти — TypeScript на Node 22.18+ без кроку збірки (лише стираний синтаксис); тести — `node --test`.
- Один публічний репозиторій-маркетплейс `GUSILLUS/ai-foundation` (MIT); плагіни `af-core`, `af-controls`, `af-handoff`, `af-metrics`. Доставка — `claude plugin marketplace add GUSILLUS/ai-foundation` + `claude plugin install af-<…>@ai-foundation`.
- Спільний код — канонічне джерело в `shared/` і копії в плагінах (`npm run sync`, `--check`); симлінків не використовуємо.
- Semver; реліз — `version` лише в `plugin.json`, запис у `CHANGELOG.md`, `claude plugin tag`.
- CI — GitHub Actions: Ubuntu + Windows, Node 22.18 + 24, Claude Code рівно з `package.json` (`config.claudeCodeVersion`) і щотижневий не блокуючий прогін на `@latest`.
- Хуки — лише exec-форма (`node` + `args`) з коротким `timeout`; внутрішня помилка → код 0 і попередження, блокування лише свідоме.
- Плагін не постачає правила чи `CLAUDE.md`: умовні інструкції — скіли з `paths`, обов’язкові правила — хуки; контекст від хука на старті — до 10 000 символів.
- Клієнтські дані (контексти, специфікації, handoff, метрики) — у `~/ai-foundation-data/`, поза будь-яким git.
- Токени — у системному сховищі ключів, окремо для кожного клієнта; запасний варіант — тека на клієнта з правами лише для власника поза даними (`~/.config/ai-foundation/secrets/<клієнт>/` / `%APPDATA%\ai-foundation\secrets\<клієнт>\`), виключена з бекапу; всередині — `_shared.env` для спільного по клієнту і `<проєкт>.env` для окремих проєктів.
- Фікстури тестів — лише синтетичні (`validate` перевіряє білим списком).
- Метрики: базова лінія — автоматично з історії сесій (`af-metrics`), далі OTel, `/usage`, `/insights`.
- Візуальна перевірка фронтенду — Playwright.
- Сторонні скіли й плагіни — лише після сканування NVIDIA SkillSpector у статичному режимі.
- Скіл чистого тексту для української та англійської на основі stop-slop; скіл `authoring` на принципах Agent Skills for Context Engineering.

## Поточний стан

**Етап 1 «каркас» завершено 20.11.2026, реліз 0.1.0 усіх чотирьох плагінів.**

- Звірка з документацією Claude Code — ADR 0001; усі відкриті питання закрито.
- `npm run validate` — 9 перевірок: маніфести, скіли, хуки, `claude plugin validate --strict`, типи, спільний код, секрети, фікстури, тести (84). CI зелений на Windows і Linux.
- `af-controls/env-guard` — PreToolUse-хук, блокує читання й редагування `.env*`; перевірено в живій сесії.
- `af-metrics` — `npm run metrics:inventory` (схема транскриптів) і `npm run metrics:baseline` (метрики за ADR 0002).
- Встановлення з GitHub у чистий профіль перевірено на Windows і Linux (`docs/install-check.md`).
- `af-core` і `af-handoff` поки порожні.

Базова лінія (10.09–20.11.2026, ADR 0002): 54 сесії, 560 промптів, 19,9 активних годин, $333,56; 7 517 викликів інструментів, 409 з помилкою (переважно Bash і Playwright); 33 відмови (17 — недоступний класифікатор автоматичного режиму); раунди правок — 31,5% ходів із правками; скіли — 31 виклик на 560 промптів.

## Наступне

Етап 2 ще не сплановано; функціональні скіли, ролі, self-learning і нові метрики — лише після затвердженого плану. Кандидати з базової лінії:

- скіли майже не використовуються — потрібні скіли, які реально спрацьовують, і вимірювання через `claude plugin eval`;
- помилки Bash і Playwright;
- відмови через недоступний класифікатор;
- повторні правки в наступному ході.

Вже обговорено для етапу 2:

- рев'ю коду за рівнями ризику (0 — без огляду … 3 — обов’язковий ретельний), конвеєр «знайти → перевірити» без субагентів і без ultrareview — ADR 0003 (пропозиція);
- низький шум у всіх відповідях агента: спершу відповідь, без похвали й переказу, твердження з доказами.

## Відкриті питання й бекліг

- ADR про доставку клієнтського контексту в сесію (перед `af-core`).
- Детальна специфікація команди init (сканування стеку, джерела вимог, шаблон контексту до 10 000 символів, перевірка актуальності).
- Механізм доступу до сховищ ключів на Windows і Linux.
- `env-guard` не розбирає команди Bash (`cat .env`).
- Тести й фікстури потрапляють у встановлений плагін.
- Як зберігати дані OTel локально.
- Які альтернативи Claude Code періодично переглядати через скаута.
- На всіх машинах підняти `cleanupPeriodDays`, щоб транскрипти CLI не зникали через 30 днів.
