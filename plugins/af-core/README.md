# af-core

Контекст проєкту, init, шаблони й робочий ланцюг для AI Foundation.

Ядро AI Foundation: агент отримує контекст проєкту з першого повідомлення, а init аналізує стек і готує контекст поза клієнтським репозиторієм. Ядро ні від кого не залежить.

Плагін входить до маркетплейсу [AI Foundation](../../README.md). Встановлення:

```bash
claude plugin marketplace add GUSILLUS/ai-foundation
claude plugin install af-core@ai-foundation
```

## Що є (0.4.0)

**Хук SessionStart** (`hooks/session-start.ts`) на кожному старті, `/clear`, відновленні й стисненні додає агенту:

1. глобальні правила — `context/global-rules.md` (до 2 000 символів);
2. картку проєкту — `~/ai-foundation-data/projects/<клієнт>/<проєкт>/context.md` (до 6 000 символів, довша обрізається по розділу) і шляхи до бази знань проєкту й спільних знань клієнта.

Проєкт визначається лише за реєстром `~/ai-foundation-data/projects.json` — за git remote (працює й у worktree), запасний варіант — за шляхом:

```json
{
  "version": 1,
  "projects": [
    { "client": "acme", "project": "portal", "remotes": ["github.com/acme/portal"], "paths": [] }
  ]
}
```

`client` і `project` — slug (a-z, 0-9, `-`, `_`). Незареєстрована тека отримує лише правила: вгадувати проєкт за назвою теки не можна (ізоляція клієнтів). Збій (зламаний реєстр, неоднозначний remote) — правила без картки й один рядок користувачу; сесія не блокується. Тека даних перевизначається змінною `AF_DATA_DIR`.

**Підказки на записи знань** (`hooks/prompt-hints.ts`, `hooks/tool-hints.ts`) — без моделі й лише за збігом:

- на промпт: слова промпту ↔ назви записів і їхні `aliases` (з урахуванням закінчень) → один рядок «релевантні записи знань: …»;
- після Read/Edit/Write: файл під `paths` запису проєкту → підказка цього запису.

Не більше трьох записів за раз; уже підказане чи прочитане в сесії не повторюється, а після `/clear` чи стиснення стан скидається. Стан — у `CLAUDE_PLUGIN_DATA`.

**Нагадування про кандидатів** (`hooks/inbox-reminder.ts`, `Stop`): коли в `_inbox/` проєкту чи клієнта з'явилися нові кандидати знань, користувач бачить один рядок із кількістю й командою розбору.

**Скіл `project-knowledge`** (`/af-core:project-knowledge [register | card | record <тема> | verify]`) веде картку й базу знань:

- `register` — додає проєкт у `projects.json` за git remote (без нього — за шляхом); наявні записи не перезаписує;
- `card` — сканує маніфести, конфіги, скрипти й структуру і заповнює шаблон картки;
- `record` — запис знань (`process`, `flow`, `feature`, `edge-case`, `decision`, `glossary`) з джерелами, у проєкт чи в спільне клієнта;
- `verify` — застарілі записи (код під `paths` змінився після `verified`) і перенесення корисного з auto memory у кандидати.

Усе показується перед записом і пишеться лише після затвердження. Детермінована частина — `scripts/knowledge.ts` (`where`, `register`, `index`, `stale`). Eval-кейси — `evals/`, запуск свідомо: `claude plugin eval plugins/af-core --runs 1 --max-cost-usd 2`.

Шаблон картки — `templates/context.md`. Рішення — ADR 0004. Кожна зміна — з тестом і записом у кореневому `CHANGELOG.md`.
