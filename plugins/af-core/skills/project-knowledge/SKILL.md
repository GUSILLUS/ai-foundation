# project-knowledge

Веде контекст проєкту в `~/ai-foundation-data/` (ADR 0004): картку, що підставляється на старті кожної сесії, і дерево знань, яке агент читає на вимогу. Нічого не пише в репозиторій проєкту.

## Стан зараз

!`node ${CLAUDE_PLUGIN_ROOT}/scripts/knowledge.ts where`

Скрипт: `node ${CLAUDE_PLUGIN_ROOT}/scripts/knowledge.ts <команда>` — `where`, `register --client <c> --project <p>`, `index`, `stale`. Він не друкує вмісту файлів і завжди завершується з кодом 0; проблеми — текстом.

## Залізні правила

- **Затвердження перед записом.** Картку й будь-який запис спершу показуєш користувачу й питаєш вибором «Записати / Змінити / Відхилити» (AskUserQuestion). Без «Записати» нічого не пишеш. Виняток — дрібна підтверджена правка, див. «Кандидати».
- **Лише з джерелом.** Кожне твердження має джерело: `файл:рядок`, команда з результатом, тікет чи PR, «зі слів користувача». Здогад без джерела не записується.
- **Секрети й чужі дані.** `.env`, ключі, токени, значення змінних оточення — ніколи не читаєш і не записуєш; лише назви змінних з `.env.example`. Дані одного клієнта не згадуєш у знаннях іншого.
- **Нічого в репозиторій.** Картка, записи, кандидати — лише в теках з виводу `where`. Назви клієнтів і проєктів не потрапляють у файли репозиторію.
- **Реєстр не перезаписується.** `projects.json` змінюєш лише через `register`; якщо він зламаний — кажеш користувачу, а не виправляєш сам.

## Режими

### register — зареєструвати проєкт

1. Якщо `where` показує «не зареєстровано», запропонуй клієнта й назву проєкту (slug: a-z, 0-9, `-`, `_`) — з remote чи назви теки — і спитай підтвердження.
2. `register --client <c> --project <p>`. Скрипт сам бере git remote, а без нього — шлях.
3. Далі — режим `card`.

### card — створити чи оновити картку

1. Збери факти лише з файлів проєкту: маніфести й lock-файли, конфіги (TS, лінтер, збирач, тести), скрипти запуску, структура верхніх тек, CI, README. Не читай `.env`, секрети, згенероване й `node_modules`.
2. Заповни шаблон `${CLAUDE_PLUGIN_ROOT}/templates/context.md` — див. [гайд картки](references/card-guide.md). Маркери `af:knowledge` залиш як є. До 6 000 символів; чого не знаєш — пропусти, не вигадуй.
3. Покажи картку цілком і питай «Записати / Змінити / Відхилити». Оновлюючи наявну — показуй лише змінені розділи.
4. Після запису — `index`, щоб розділ «Знання» картки відповідав дереву.

### record — додати чи оновити запис знань

1. Визнач гілку й тему: проєкт чи спільне клієнта (процес команди, деплой, словник, що однакові для всіх проєктів клієнта, — у спільне). Перевір, чи немає вже запису на цю тему (`_index.md`) — тоді оновлюй його, а не створюй дублікат.
2. Напиши запис за [форматом запису](references/record-format.md): frontmatter з `summary`, `type`, `aliases`, `paths`, `sources`, `verified`; до 150 рядків; посилання на інші записи — `[[гілка/запис]]`.
3. Покажи й питай «Записати / Змінити / Відхилити».
4. Після запису — `index`. Помилки, які він друкує (`✘`), виправ до кінця задачі.

### verify — перевірити актуальність

1. `stale` — записи, код під якими змінився після перевірки, і записи без `paths` чи коміту.
2. Для кожного застарілого: звір із кодом, запропонуй правку з джерелом, після затвердження онови `verified` (дата й короткий хеш `git rev-parse --short HEAD`).
3. Auto memory Claude Code (шлях — у `where`): прочитай `MEMORY.md` і тематичні файли, стійке й підтверджуване перенеси в кандидати (`_inbox/`). Саму auto memory не змінюй.
4. Розбери кандидати — див. нижче — і заверши `index`.

## Кандидати

Під час звичайної роботи, коли з'ясовуєш щось неочевидне про проєкт, не переривай задачу: поклади кандидата в `knowledge/_inbox/` (чи `_shared/knowledge/_inbox/`) окремим файлом з полями `target` (куди), `confidence` (`confirmed` / `likely`), `sources` і текстом.

| Випадок | Що робиш |
| --- | --- |
| Дрібна правка наявного запису, підтверджена кодом (`файл:рядок`) чи прямо користувачем — змінився шлях, команда, назва | Застосовуєш одразу; у кінці відповіді один рядок «знання оновлено: `<запис>` — …» |
| Новий запис, нова гілка, `likely`, суперечність з наявним | Пакетом у кінці задачі чи перед handoff: «Записати / Змінити / Відхилити» для кожного |
| Здогад без джерела | Не записуєш |

Прийнятий чи відхилений кандидат видаляєш з `_inbox/`; відхилений не пропонуєш знову в цій сесії.

## Red flags — зупинись

- Хочеш записати без показу користувачу → спершу покажи.
- Пишеш «зазвичай у таких проєктах…» → це здогад, джерела немає.
- Тягнеш у картку все підряд → картка — орієнтир на 6 000 символів, деталі — у записи.
- Створюєш запис, а схожий уже є в `_index.md` → онови наявний.
