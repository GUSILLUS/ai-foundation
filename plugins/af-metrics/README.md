# af-metrics

Метрики використання агентів для AI Foundation.

Метрики: аналізатор історії сесій Claude Code для базової лінії (лише читання, лише агрегати) і подальший збір через вбудовану телеметрію. Результати — у ~/ai-foundation-data/metrics/, без вмісту транскриптів і клієнтського коду.

Плагін входить до маркетплейсу [AI Foundation](../../README.md). Встановлення:

```bash
claude plugin marketplace add GUSILLUS/ai-foundation
claude plugin install af-metrics@ai-foundation
```

## Аналізатор історії сесій

Лише читає транскрипти Claude Code (`<CLAUDE_CONFIG_DIR>/projects/**/*.jsonl`, за замовчуванням `~/.claude`). Визначення метрик — `docs/decisions/0002-metrics-baseline.md`.

```bash
npm run metrics:baseline              # базова лінія: baseline-<дата>.md і .json
npm run metrics:baseline -- --since 2026-11-01 --anonymize
npm run metrics:inventory             # опис даних для аналізу схеми
# або з установленої копії:
node <тека плагіна>/scripts/analyze-history.ts [--inventory] [--since YYYY-MM-DD] [--anonymize] [--config-dir <тека Claude Code>] [--out <тека звіту>]
```

Звіти пишуться в `~/ai-foundation-data/metrics/`.

- **Базова лінія** містить лише агрегати: лічильники, токени, вартість, назви інструментів, скілів, субагентів і моделей. Текстів промптів і відповідей, шляхів файлів і команд у ній немає. Назви проєктів — справжні (остання частина робочої теки); `--anonymize` замінює їх на `project-1`, `project-2`, … — для звіту, яким треба поділитися.
- **Інвентаризація** описує структуру транскриптів: типи записів, ключі без значень, переліки, версії. Назв проєктів не містить — її можна пересилати для аналізу схеми після оновлення Claude Code.

- **Контекст і знання** (ADR 0004, п. 9): обсяг результатів інструментів у символах, кількість і обсяг Read/Grep/Glob до першої правки в сесії, які записи бази знань агент читав (`проєкт: гілка/запис` чи `клієнт: …` — без назв клієнтів і проєктів).

## Аудит плагінів, скілів і MCP

Скіл `plugin-audit` (`/af-metrics:plugin-audit`) або скрипт напряму — лише читає, нічого не видаляє:

```bash
npm run metrics:audit                 # вікно — останні 30 днів
npm run metrics:audit -- --all        # усі наявні транскрипти (перший запуск)
node <тека плагіна>/scripts/plugin-audit.ts [--days <n> | --since YYYY-MM-DD | --all] [--print] [--config-dir <тека>] [--claude-json <файл>] [--out <тека>]
```

Звіт `plugin-audit-<дата>.md` і `.json` у `~/ai-foundation-data/metrics/`. Для кожного плагіна, окремого MCP-сервера й особистого скіла, агента чи команди: використання за вікно (скіли, субагенти, слеш-команди, виклики й помилки MCP, відмови наших хуків), оцінка символів на старті, конфлікти з правилами AI Foundation і вердикт «лишити / переглянути / прибрати» з причиною. Пороги — `THRESHOLDS` у `lib/audit.ts`.

- Джерела: `installed_plugins.json` і `settings.json` теки Claude Code, теки встановлених плагінів, `skills/`, `agents/`, `commands/` теки Claude Code, `~/.claude.json` (лише імена MCP-серверів і рівень — без `env`, заголовків і шляхів проєктів).
- Оцінка «на старті» — за описами в списку скілів, агентів і команд та інструкціями MCP з транскриптів. Схеми інструментів MCP і контекст хуків за плагінами не розподіляються — точні числа дає `/context`, і скіл просить його вивід.
- Конфлікти — евристики: хук SessionStart чи UserPromptSubmit поруч з `af-core`, PreToolUse на Read/Edit/Write поруч з `env-guard`, згадка субагентів в інструкціях, однакові назви скілів у різних джерелах.
