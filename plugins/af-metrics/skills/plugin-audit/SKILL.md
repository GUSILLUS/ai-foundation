# plugin-audit

Показує, що з встановленого реально працює, а що лише займає контекст. Рішення про видалення ухвалює користувач — по одному елементу.

## Залізні правила

- **Нічого не видаляєш без підтвердження.** Кожен елемент з вердиктом «прибрати» — окреме питання вибором «Прибрати / Лишити / Пізніше» (AskUserQuestion). Без «Прибрати» команду не виконуєш. Список із кількох елементів не підтверджується одним «так».
- **Наші плагіни `af-*` не видаляєш.** Для них — лише висновок; зміни робляться в репозиторії AI Foundation.
- **Лише агрегати.** Транскрипти, `~/.claude.json`, `settings.json` і конфіги MCP сам не читаєш — тільки звіт скрипта. Значень `env`, заголовків, токенів не виводиш.
- **Особисте не видаляєш, а переносиш** у `~/.claude/_removed/` — так його легко повернути.

## Порядок

1. Запусти скрипт з аргументами користувача; без них — вікно 30 днів. Перший аудит на машині (у `~/ai-foundation-data/metrics/` ще немає `plugin-audit-*.md`) — з `--all`.

   ```
   node ${CLAUDE_PLUGIN_ROOT}/scripts/plugin-audit.ts [--all | --days <n> | --since <YYYY-MM-DD>]
   ```

   Скрипт пише `plugin-audit-<дата>.md` і `.json` і друкує шлях. Прочитай `.md`.
2. Попроси користувача виконати `/context` і вставити вивід (агент сам його не запускає). Порівняй розділи з оцінкою «на старті» у звіті; якщо розбіжність велика — назви її й довіряй `/context`.
3. Відповідь — коротко, з числами:
   - підсумок: вікно, сесій, скільки «прибрати / переглянути / лишити»;
   - таблиця лише «прибрати» й «переглянути»: назва, використань, символів на старті (з `/context`, якщо є), причина;
   - для «переглянути» — що саме перевірити (конфлікт, помилки MCP, вимкнений плагін); евристики (згадка субагентів, перетин хуків) так і називай — евристикою;
   - якщо вікно коротше 14 днів — скажи, що для «прибрати» даних замало.
4. Для кожного «прибрати» — окреме питання. Після «Прибрати» виконай команду зі звіту (`claude plugin uninstall …`, `claude mcp remove … -s …`; для рівня `local` — у теці відповідного проєкту, яку назве користувач) або перенеси особисте у `~/.claude/_removed/`. Після кожної дії покажи результат команди.
5. Наприкінці — що змінено, що відкладено, і нагадай про `/reload-plugins` або нову сесію.

## Як читати вердикти

- **прибрати** — нуль використань за вікно ≥ 14 днів (скіли, агенти, команди, виклики MCP).
- **переглянути** — вимкнено; порожній плагін; помилки MCP ≥ 5 і ≥ 20% викликів; рідко (≤ 2) і дорого (≥ 2 000 символів на старті); конфлікт з правилами (хук SessionStart чи UserPromptSubmit поруч з af-core, PreToolUse на Read/Edit/Write поруч з env-guard, згадка субагентів, однакові назви скілів).
- **лишити** — використовується без зауважень, або плагін лише з хуками без конфліктів (їхню роботу транскрипт не показує — це сказати).

Плагін лише з хуками може бути корисним без жодного «використання» в транскрипті: не радь його прибрати на підставі нуля.
